Add the test-strategy skill. It writes down how a product is tested: the journeys and business rules that must never break, the test that proves each at the level where it belongs (or "none yet"), how tests meet outside services and stored data, abuse tests, test data, what runs on every change, and the gaps as work, most serious first. It checks what existing tests really prove and whether anything runs them. The project map now counts a written test strategy as a start on the tests item, never as tests.
